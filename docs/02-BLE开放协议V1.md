# 02-BLE开放协议V1

## 1. 协议版本

- 当前版本：`1.3.0`
- 包头建议：`[ver, cmd, ...payload]`
- `ver` 取值建议：`0x01`

## 2. BLE 基础定义

- Service UUID：`4fafc201-1fb5-459e-8fcc-c5c9c331914b`
- Characteristic UUID：`beb5483e-36e1-4688-b7f5-ea07361b26a8`
- Characteristic 属性：`WRITE` + `WRITE_NO_RESPONSE` + `NOTIFY` (或 `INDICATE`)

设备名格式：
`kmpd-XXXX`
`pindou-XXXX`
命名格式必须任选其一，否则将无法搜索的到

## 3. 指令集 V1

### 3.1 清屏

```text
[0x01]
```

### 3.2 绘制像素

```text
[0x02, R, G, B, X1, Y1, X2, Y2, ...]
```

- `R/G/B`: 0~255
- `Xi/Yi`: 像素坐标
- 单包可携带多个点位

### 3.3 提交显示

```text
[0x03]
```

### 3.4 亮度调节

```text
[0x04, Value]
```

- `Value`: 0~100 (亮度百分比)
- 设备端应在收到此指令后实时或渐变应用亮度，无需等待 `0x03` 显示指令。

## 4. 推荐扩展指令（V1.1+）

### 握手请求

```text
[0x10, nonce(8 bytes)]
```

### 握手响应

```text
[0x11, sign(16/32 bytes)]
```

### 心跳

```text
[0x13, timestamp(4 bytes)]
```

### 4.1 设备按键事件（上行指令）

```text
[0x05] // 触发事件：切换上一个颜色
[0x06] // 触发事件：切换下一个颜色
```

- 硬件端需对实体按键做防抖处理（建议 `20~50ms`）。
- 硬件端通过主 `NOTIFY` 特征值主动向 App 发送此指令。
- App 收到事件后切换底部色卡当前色，并可下发临时色号提示命令。

### 4.2 查询硬件信息

App 下发：

```text
[0xA1, 0x00, 0xA1, 0x00, 0xBF]
```

- 固定请求帧：`A1 00 A1 00 BF`。
- 第 1 个字节为查询帧头 `0xA1`。

设备通过 `NOTIFY` 返回：

```text
[0xA1, Enabled, Width, Height, Major, Minor, Build]
```

- `Enabled`：`0x01` 表示设备已启用，`0x00` 表示未启用。
- `Width` / `Height`：设备物理像素宽高，单位为点；例如 `0x68` 表示 `104`。
- `Major` / `Minor` / `Build`：固件版本号。
- App 必须以该宽高进行图纸和色号提示的边界校验。

示例：104×104 设备，固件版本 `1.1.1`：

```text
[0xA1, 0x01, 0x68, 0x68, 0x01, 0x01, 0x01]
```

### 4.3 显示临时色号提示

用于在设备物理左上角临时覆盖显示色号，例如 `A1`、`B15`。设备端负责计时和恢复底层图案，App 不需要清屏或重发整图。

App 下发：

```text
[0xA2, X, Y, DurationLow, DurationHigh, TextLength, ASCII...]
```

- `X` / `Y`：色号提示左上角坐标；默认使用 `0x00, 0x00`。
- `DurationLow` / `DurationHigh`：显示时长，单位毫秒，使用 `uint16` 小端序；`3000ms = 0xB8, 0x0B`。
- `TextLength`：文本长度，当前支持 `1~3` 个字符。
- `ASCII...`：大写字母、数字或 `?`，例如 `A1` 为 `0x41, 0x31`。
- 固件需内置 `A-Z`、`0-9`、`?` 的 `5×7` 点阵字库；字符间隔建议为 1 点。
- 新命令到达时，设备必须取消旧提示并重新开始计时，以最后一次命令为准。

示例：在 `(0, 0)` 显示 `A1`，持续 3 秒：

```text
[0xA2, 0x00, 0x00, 0xB8, 0x0B, 0x02, 0x41, 0x31]
```

设备端处理要求：

1. 基础图案数据与临时提示数据必须分层保存。
2. 输出时临时提示层优先于基础图案层。
3. 时长结束后只清除临时提示层，基础图案自动恢复。
4. 提示显示期间，App 断开连接也必须按时恢复。
5. 提示区域超出设备边界时拒绝命令并返回错误码，不可静默裁剪。

### 4.4 取消临时色号提示

App 下发：

```text
[0xA3]
```

设备行为：

```text
取消当前提示计时器 → 清空临时提示层 → 刷新基础图案层
```

适用场景：切换图纸、清屏、发送整图、用户主动关闭提示。

### 4.5 扩展命令执行结果（上行指令）

设备处理 `0xA1`、`0xA2`、`0xA3` 后，通过 `NOTIFY` 返回：

```text
[0xA0, RequestCommand, Status]
```

- `RequestCommand`：对应请求命令，例如 `0xA2`。
- `Status`：`0x00` 表示成功；其他值为错误码。

示例：临时色号提示显示成功：

```text
[0xA0, 0xA2, 0x00]
```

## 5. 错误码约定

- `0xE1`: 未授权
- `0xE2`: 包格式错误
- `0xE3`: 越界坐标
- `0xE4`: 频率超限
- `0xE5`: 版本不兼容
- `0xE6`: 临时提示文本为空、长度超限或包含不支持字符
- `0xE7`: 临时提示坐标或文字尺寸越界
- `0xE8`: 临时提示层不可用或缓冲不足

## 6. 分包建议

- 单包建议不超过 180 字节
- 大图分片发送，分片顺序必须可重组
- 每批次发送结束后调用 `0x03`

## 7. 向后兼容策略

- V1 命令长期保留：`0x01/0x02/0x03`
- 新能力通过新 cmd 添加，不覆盖旧 cmd 语义
- 破坏兼容变更必须升级大版本
